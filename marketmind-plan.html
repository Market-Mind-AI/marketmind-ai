The core architectural decision

It is a deterministic enrichment DAG with two genuine LLM reasoning steps — not an autonomous agent swarm.

Build it as a LangGraph StateGraph, keep the MOS arithmetic in pure, auditable Python, and reserve LLM calls for the two places they truly add value. This keeps the system debuggable, near-zero-cost, and academically defensible — and it is the single decision that makes the project finishable by two people.

Section 01 — End-to-end pipeline

From a catalog to a cited recommendation

Eight stages. Only two of them call an LLM. Checkpointing sits under the whole graph, so a rate-limit failure at product 300 resumes rather than restarts.

1
Upload Streamlit → FastAPI POST /catalogs

Catalog CSV/Excel (+ optional product images). Returns 202 + job_id immediately; a background task does the work.

2
Ingest IngestionNode

pandas / openpyxl + Pydantic validation → normalized products[], files to object storage, rows to Postgres.

3
Extract attributes Haiku 4.5 · vision

category · material · color · use-case · keywords + per-field confidence. Text-only fallback when no image; Ollama Qwen2.5-VL fallback in dev.

4
Enrich — parallel fan-out LangGraph Send · 7-day cache

DataForSEO Trends · World Bank + IMF · eBay Browse. Each connector behind a swappable Connector interface. (Reddit / Comtrade optional, flag-gated.)

5
Score MOS pure Python

winsorize → min-max → weighted sum. Deterministic, unit-testable, exactly reproducible. No LLM in the arithmetic.

6
Geo match GeoMatchingNode

Rank countries from World Bank GNI-PPP + e-commerce penetration + eBay listing density.

7
Generate report Sonnet 4.6 · cited schema

Per-category synthesis with 2–3 per-product drill-downs. Every claim cites a specific datum via a Citation Pydantic schema.

8
Package & visualize Streamlit dashboard

Stacked-bar factor contribution · ranked table · country choropleth — the explainability layer.

Section 02 — Component architecture

A small stack, deliberately chosen

Every component earns its place. The recurring theme: pick the option that satisfies the thesis objective at the lowest operational cost.

Frontend

Streamlit

Community Cloud · free

In the brief and fastest to a thesis demo. Native dataframe + chart widgets; stacked bars and a choropleth are ~20 lines each.

API

FastAPI · async

Pydantic contracts

Async fits the parallel connector fan-out. Pydantic models are the shared contract with LangGraph state. Free OpenAPI docs.

Orchestration

LangGraph StateGraph

Send · checkpoint/resume

Fixed DAG, parallel scatter/gather, conditional fallback edges. CrewAI / AutoGen explicitly rejected — wrong abstraction for a pipeline.

Scoring

Pure Python

NumPy · scikit-learn

Deterministic and reproducible — mandatory for the methodology chapter. The MOS arithmetic never touches an LLM.

Relational store

PostgreSQL 16

+ pgvector ready

Products, enrichment cache, MOS results, LangGraph checkpoints — one database does it all.

Vector store

ChromaDB · embedded

optional · lightly used

Honors the proposal, zero infra. Scope = report grounding only. pgvector is the cloud migration path.

Object storage

S3-compatible

boto3 · S3_ENDPOINT_URL

Identical code across S3 / GCS / Azure Blob / SeaweedFS. Product images and uploaded catalogs.

Async work

FastAPI BackgroundTasks

no Celery / Redis

A batch academic tool serves no concurrent users. Status row in Postgres for progress. Celery is documented as the scale-out path, not built.

LLM provider

LLM_PROVIDER switch

Claude ⇄ Ollama

Qwen2.5-VL locally for free dev; Claude API for the demo. Flip with one env var.

Direct answer — the Amazon question

Amazon does not give third parties market intelligence.

The official channels are off-limits — economically and, for PA-API, legally. The clean path is legitimate resellers, and Amazon data used mainly as a validation benchmark. The reasoning itself is a strong methodology section.

Section 04 — Market Opportunity Score

A score you can defend, not just compute

Frame the methodology on the OECD/JRC Handbook. Because aggregation is linear, explainability is exact: contribution = weight × score.

PROPOSED INDEX — implement config-driven, then analyze & reconcile

Recommended reconciliation → Trend, Seasonality and keyword-volume all derive from one DataForSEO signal (~55% shared-source). Report this honestly, then present a validated 3-factor MOS — Demand Trajectory ~45% · Market Attractiveness ~35% · Marketplace Demand ~20% — with an equal-weights baseline. A clean, independent, fully-validated score beats five factors where two are mostly imputed. The journey proposed → analyzed → validated is what earns marks.

Validation · primary

Keepa BSR Spearman

50–80 products across 3–5 categories. Spearman ρ between MOS rank and inverse-BSR rank; report ρ, p, 95% CI. ρ>0.35, p<0.05 is defensible — the number that turns "we invented a score" into a contribution.

Validation · secondary

Sensitivity check

Equal-weights baseline comparison + a basic ±25% weight perturbation. Cheap, and shows the ranking isn't an artifact of one weight.

Caveat to honor

Seasonality on 12 months

STL wants ≥24 months. Either pull longer Trends history or drop it from the composite and surface it as a separate qualitative flag — don't claim a decomposition you can't support.

Section 05 — Cloud-agnostic IaC

Portable Terraform, honestly framed

The portability boundary is the container API. Claim "cloud-portable IaC," not "multi-cloud-live." You satisfy the objective with modular Terraform deployed once + a written portability analysis — not by standing up a second cloud.

Phase 1 · required

Local

docker-compose

FastAPI · Streamlit · Postgres+pgvector · (optional Chroma). .env secrets, zero Terraform. This is your demo and your MVP.

Phase 2 · optional stretch

Single cloud

GKE Autopilot / Cloud Run

Scale-to-zero on the $300 GCP credit, or one VM running docker-compose. Modular Terraform: compute · postgres · object-storage · secrets behind stable interfaces. ≈ €0–30/mo.

Phase 3 · cut

Multi-cloud

does not exist

Replaced by a written portability analysis. A 3-cloud proof is months of infra work that earns ~30 seconds of examiner attention.

Section 06 — Scope discipline

The line between finishing and not

The easy failure mode for this TFM is over-scope. Agree this list before writing code — and protect it.

✦ Core MVP — build · validate · write up
  • ✓CSV/Excel ingestion + Pydantic validation
  • ✓Image → attribute extraction (Haiku vision) — the headline gen-AI feature
  • ✓Three connectors: DataForSEO Trends · World Bank + IMF · eBay Browse
  • ✓Pure-Python MOS with exact additive explainability
  • ✓One Sonnet report node, per category, cited schema
  • ✓Streamlit dashboard — stacked bars + ranked table + choropleth
  • ✓One validation done well: Keepa BSR Spearman
  • ✓One modular Terraform deploy + portability analysis

  • ✕Multi-cloud / second Terraform provider → written analysis instead
  • ✕Celery + Redis → FastAPI BackgroundTasks
  • ✕HS-code RAG + UN Comtrade — highest-effort, lowest-reliability. Strong future-work candidate.
  • ✕Reddit → optional, best-effort connector
  • ✕Seasonality as a real STL factor on 12 months → qualitative flag
  • ✕Dedicated vector DB as a service → embedded / skip
  • ✕COINr/Sobol · AHP · predictive validity → future rigor
